# MSG 뷰어 명세 평가

평가일: 2026-09-17

**최종 판정: 명세 수준 ADVISORY APPROVED — 구현 착수 가능.**

사용자의 `ooo evaluate` 요청에 따라 현재 산출물인 `seed.yaml`과 `SPEC.md`를 평가했다. 구현을 막을 요구사항 누락이나 내부 모순은 발견하지 못했다. 필수 수정 사항은 없다. 앱 구현·EXE 빌드·실행·성능 검증은 아직 수행하지 않았다.

## 평가 방식과 범위

- `ouroboros-evaluate` 스킬의 3단계 절차와 설치된 `evaluator.md` 역할을 적용했다.
- 현재 노출된 도구와 검색 가능한 도구 목록을 확인했으나 호출 가능한 Ouroboros 평가 MCP 도구가 없었다. 문서화된 로컬 대체 절차로 평가했으며 세션 ID나 엔진 평가 결과를 생성하지 않았다.
- Stage 1은 실제 Python 명령 실행으로 확인했고, Stage 2는 별도 검토 에이전트가 승인된 요구사항과 문서를 대조했다.
- 이번 결과는 정성적 자문 평가다. 이전 명세 QA의 0.97점을 이번 평가 점수로 재사용하지 않았고 새 종합 점수도 부여하지 않았다.
- 평가 대상 명세는 수정하지 않았다. 이전 QA 당시의 SHA-256과 현재 파일이 일치한다.

## Stage 1 — 기계적 검증: PASS

Python과 설치된 Ouroboros 0.51.7의 실제 Seed 모델을 사용해 아래 8개 검사를 실행했다. 명령 종료 코드는 0이며 실패 항목은 없다.

| 검사 | 결과 |
| --- | --- |
| 중복 키를 허용하지 않는 YAML 파싱과 `Seed.model_validate` | 통과 |
| AC-01~08 식별자의 중복·누락 여부 | 통과 |
| 평가 원칙 가중치 합계 | 통과, 합계 1.0 |
| 검증 계획에서 참조한 `SPEC.md` 존재 | 통과 |
| 기존 QA·감사 기록 JSON 파싱 및 참조 파일 | 통과 |
| `seed.yaml`과 이전 검토 해시 비교 | 일치 |
| `SPEC.md`와 이전 검토 해시 비교 | 일치 |
| UTF-8 텍스트 무결성·줄 끝 공백·최종 개행 | 통과 |

원자료와 검토 파일 해시는 [evaluation-mechanical.json](evaluation-mechanical.json)에 기록했다. 현재 문서는 실행 프로그램이 아니므로 컴파일, 앱 단위 테스트, GUI 동작 관찰과 코드 커버리지는 이번 문서 검증에 해당하지 않는다. 해당 검사를 성공한 것으로 기록하지 않았다.

`dist/MsgViewer.exe`, `reports/acceptance.md`, `reports/performance.csv`는 아직 존재하지 않는다. 이들은 향후 구현 산출물이므로 명세의 형식 오류로 처리하지 않으며, 제품 완료 증거로도 취급하지 않는다.

## Stage 2 — 요구사항·의미 검토: ADVISORY PASS

| AC | 명세 평가 | 제품 실행 검증 |
| --- | --- | --- |
| 01 | 동일 x86 EXE, Windows 10 x86·x64 / Windows 11 x64, 오프라인·추가 설치 없음 반영 | 미검증 |
| 02 | 열기·닫기·종료·창 X 및 한 번에 한 문서 흐름 반영 | 미검증 |
| 03 | 본문 서식·표·내부 이미지 보존과 외부 리소스 미요청 구분 | 미검증 |
| 04 | 마우스 텍스트 선택·우클릭 복사와 붙여넣기 확인 기준 명시 | 미검증 |
| 05 | 첨부 이름 목록 → 다른 이름으로 저장, 실제 바탕화면 기본값, 내용 보존 반영 | 미검증 |
| 06 | 닫기·정상 종료 정리, 비정상 종료 후 다음 실행 정리, 사용자 저장 첨부 보존 반영 | 미검증 |
| 07 | 앱 장식 제거와 메일 본문 표현 유지 구분 | 미검증 |
| 08 | 7~8MB 목표와 더 작은 파일 허용, 속도 우선·RAM 추가 허용, 실측 계획 반영 | 미검증 |

크기 목표를 하한이나 배포 크기 보장으로 바꾸지 않았다. 사용자와 합의되지 않은 초 단위 SLA, RAM 상한 또는 최대 MSG 크기를 추가하지 않았다. 취소·실패 처리와 임시 경로 소유권 확인은 승인된 동작의 정확성을 위한 지침으로 판단했다.

오해를 방지하는 완료 기준도 포함되어 있다. 파일이나 보고서의 존재만으로 동작 통과를 인정하지 않고, 미시험 OS는 미검증으로 남기며, Windows 자체 기록과 사용자가 저장한 첨부파일은 삭제 대상에서 제외한다. 기본 모호성 값 0.15는 측정된 평가값이 아님을 명시한다.

## Stage 3 — 다중 모델 합의: 미실시

사용자가 다중 모델 합의를 별도로 요청하지 않았고, Stage 2에서 추가 합의를 필요로 할 요구사항 충돌이나 높은 모호성은 발견하지 못했다. 별도 에이전트의 문서 검토를 다중 모델 투표나 엔진 합의 결과로 표시하지 않는다.

## 구현 단계에서 확인할 사항

아래는 명세 승인에 대한 필수 수정 사항이 아니라 구현 후 입증해야 할 항목이다.

1. 선택한 MSG 파서·렌더러가 추가 설치 없이 세 OS 구성에서 본문과 첨부를 정확히 처리하는지 확인한다.
2. 최종 EXE의 실제 크기와 최초 실행·MSG 열기·종료 시간을 측정한다. 시간 합격선은 합의되지 않았으므로 동일 조건 비교와 실측 결과로 성능 판단 근거를 제시한다.
3. 압축 RTF, 저장소형 첨부, 표와 삽입 이미지 등 대표 샘플에서 호환성을 확인한다. 제한을 보고하는 것만으로 필수 동작 검증을 대체하지 않는다.
4. 정상 닫기·종료 및 강제 종료 후 재실행에서 임시자원 정리를 실제로 관찰한다.

다음 권장 작업은 `ooo run`으로 승인된 Seed의 구현을 시작한 뒤, 실제 실행 산출물에 대해 다시 평가하는 것이다.
