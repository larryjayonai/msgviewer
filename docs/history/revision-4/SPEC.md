# 오프라인 MSG 뷰어 구현 명세

이 문서는 사용자가 승인한 요구사항의 구현 및 검증 지침이다. 기준 Seed는 `seed.yaml`이다. 현재 작업의 산출물은 명세이며 앱, EXE 또는 실측 결과가 이미 만들어졌다는 의미는 아니다.

수정 4: x86 공용 EXE를 유지한다. 사용자가 지정한 버튼 좌우 배치, 보내는 사람과 초 단위 전송 일시의 같은 줄 표시, 받는 사람·참조·숨은참조 각 한 줄, 긴 제목의 줄바꿈, 본문과 맨 아래 첨부파일 섹션을 반영했다.

## 1. 제품과 배포

Windows 10 x86·x64와 Windows 11 x64에서 같은 x86 EXE 하나로 동작하는 휴대용 MSG 뷰어를 만든다. Windows 11의 32비트 OS는 지원 대상으로 가정하지 않는다. 사용자 PC에는 Outlook, 별도 런타임, 브라우저 또는 다른 구성요소를 설치할 필요가 없어야 하며 첫 실행도 인터넷 없이 가능해야 한다. Windows 기본 구성요소 사용은 허용한다.

인터넷이 연결된 PC에서도 앱과 앱이 호스팅한 본문 렌더러는 인터넷 요청을 시도하지 않는다. 원격 이미지·CSS·글꼴·스크립트 요청, 업데이트 확인, 사용 통계, 오류 전송, 온라인 번역, 언어팩 다운로드를 수행하지 않는다. 메일의 외부 링크를 눌러 웹 브라우저를 실행하거나 외부 통신으로 넘기는 동작도 제공하지 않는다. 표시용 원문과 텍스트 선택·복사는 유지한다. 앱이 유발한 통신과 Windows의 독립적인 백그라운드 통신은 구분하며, OS 전체의 통신을 끄라는 요구로 확대하지 않는다.

EXE의 목표 크기는 7~8MB다. 더 작으면 그대로 배포한다. 크기 측정은 정확한 바이트 수, 십진 MB와 이진 MiB를 함께 제시하며 목표 판정의 측정 관례는 8,000,000바이트 이하로 둔다. 8MB를 넘으면 목표 미달임을 보고한다. 크기 목표를 달성했다고 주장하기 위해 기능·호환성 요구를 생략하지 않는다.

우선순위는 필수 기능과 호환성을 지키면서 최초 실행, MSG 열기, 종료를 빠르게 하는 것이다. 세 속도 사이의 별도 순위는 정하지 않았다. RAM 추가 사용은 허용되며 임의의 최대 RAM, 최대 MSG 용량 또는 초 단위 SLA를 사용자 요구처럼 추가하지 않는다. 압축·자기압축 해제 등은 최종 파일 크기만 보지 말고 최초 실행 비용까지 비교한다.

## 2. 사용 흐름

| 동작 | 결과 |
| --- | --- |
| 실행 | 빈 뷰어의 최상단 왼쪽에 열기·닫기, 오른쪽에 언어 변경·종료 버튼 표시 |
| 열기 | 파일 선택 창에서 MSG 하나를 선택해 표시 |
| 다른 MSG 열기 | 같은 화면의 현재 문서를 교체하고 이전 문서의 임시자원 정리 |
| 닫기 | 현재 MSG와 임시자원을 정리하고 앱은 빈 상태로 유지 |
| 종료 / 창 X | 앱이 만든 임시자원을 정리한 후 프로세스 종료 |
| 본문 선택 → 우클릭 복사 | 선택한 텍스트를 클립보드로 복사 |
| 메일 기본정보 선택 → 우클릭 복사 | 보내는 사람·전송 일시·받는 사람·참조·숨은참조·제목의 선택한 값을 텍스트로 복사 |
| 첨부파일 이름 클릭 | 바탕화면을 기본 위치로 하는 다른 이름으로 저장 창 표시 |
| 언어 변경 버튼 | 한국어·영어·프랑스어·일본어 중 선택해 앱 UI에 즉시 적용 |

한 번에 문서 하나만 표시한다. 폴더별 메일 목록, 검색·색인, 다중 문서 화면, 첨부 실행·미리보기는 이번 범위에 포함하지 않는다. 위 사용 흐름을 위한 취소·오류 처리와 빈 상태의 버튼 처리는 일반적인 GUI 동작으로 구현한다. 파일 선택을 취소해도 현재 문서를 잃지 않게 하고, 읽을 수 없는 파일은 설명 가능한 오류로 처리한다. 이 오류 처리는 새 제품 기능을 추가하는 의미가 아니다.

## 3. 본문과 첨부

일반 이메일 MSG를 우선 지원한다. 일정·연락처 전용 뷰와 암호 해제·권한 인증은 이번 필수 범위에 포함하지 않는다. 지원하지 못하는 일정·연락처·암호화·권한 보호 메시지를 열면 선택한 UI 언어로 이유를 표시한다. 내용을 읽지 못했는데 빈 본문을 정상 열람처럼 표시하거나, 온라인 인증을 시도하는 동작은 하지 않는다.

본문 위에는 보내는 사람·전송 일시·받는 사람·참조·숨은참조·제목의 여섯 항목을 아래 GUI 배치대로 표시한다. 각 항목의 값은 읽기 전용이며 마우스 선택과 우클릭 텍스트 복사를 지원한다. UI 언어 변경은 항목 이름에 적용하고 실제 메일 값은 번역하지 않는다. 원본에 없는 값은 선택된 UI 언어로 정보 없음을 표시하며 임의의 보내는 사람이나 날짜 등을 만들지 않는다.

전송 일시는 메시지의 전송 시각을 연·월·일·시·분·초까지 표시한다. 기본 표현은 24시간제 `YYYY-MM-DD HH:mm:ss`다. 시간대는 실행 PC의 Windows 시간대를 기본 표시 기준으로 삼되, 원본 시각의 시간대 근거 없이 임의로 변환하지 않는다. 이 형식과 시간대 기본값은 요구된 정밀도를 구현하기 위한 기본값이며 별도로 지정된 사용자 시간대 요구는 아니다. 전송 시각이 없으면 파일 생성·수정 시각이나 현재 시각으로 대체하지 않는다.

숨은참조는 MSG에 저장된 정보만 표시한다. 값이 없는 경우 정보 없음으로 표시하며 실제 전송에 숨은참조 수신자가 없었다고 단정하지 않는다. 외부 조회로 누락된 값을 복구하지 않는다.

메일 본문의 글자, 서식, 표와 내부 삽입 이미지를 최대한 원본대로 읽을 수 있게 표시한다. 단순화 대상은 앱의 장식이다. 메일을 항상 일반 텍스트로 바꾸거나 본문 이미지를 모두 제거하는 방식은 허용하지 않는다. 표의 행·열, 읽는 순서, 내용의 누락 여부와 내부 이미지 표시를 대표 MSG로 확인한다. Outlook과 모든 픽셀이 같은 화면까지는 보장 범위가 아니다.

본문의 한글·영문·표 안의 텍스트를 마우스로 선택하고 우클릭으로 복사할 수 있어야 한다. 복사의 필수 결과는 텍스트이며 HTML 서식까지 클립보드에 보존하는 기능은 추가 요구하지 않는다. 외부 네트워크의 리소스를 자동 요청하지 않는다. MSG 안에 없는 원격 이미지는 오프라인에서 복원할 수 없으므로 빈 자리나 간단한 대체 표시를 허용한다.

맨 아래 첨부파일 섹션에는 일반 첨부의 파일명을 한 줄에 한 파일씩 표시한다. 일반 첨부가 없으면 섹션을 숨기지 않고 한국어 UI에서는 `없음`을 표시하며 다른 UI 언어에서는 같은 의미의 번역을 표시한다. 본문 삽입 이미지와 서명·로고 이미지는 본문에 표시하고 첨부 목록에서는 제외한다. 따라서 본문 이미지만 있는 메일도 일반 첨부가 0개이면 `없음`을 표시한다. 파일 확장자가 이미지라는 이유만으로 일반 사진·이미지 파일 첨부까지 숨기지는 않는다. 본문 내 사용 여부와 메시지의 첨부 정보를 바탕으로 구분한다.

첨부 이름을 클릭하면 다른 이름으로 저장만 제공한다. 저장 대화상자를 열 때마다 실제 사용자의 바탕화면을 기본 위치로 지정한다. 바탕화면 리디렉션이나 로컬라이즈된 경로를 고려하며 `C:\Users\사용자\Desktop`을 고정 경로로 쓰지 않는다. 사용자가 경로와 이름을 바꾸거나 취소할 수 있어야 한다. 일반 파일 첨부는 저장 전후 바이트 또는 해시를 비교한다.

첨부된 MSG도 목록에서 저장만 지원하며 그 자리에서 열거나 미리 보지 않는다. 일반 파일 형태의 MSG 첨부는 원본 바이트를 보존한다. 저장소형 메일 첨부는 제목·주소·날짜·본문·내부 첨부 등의 내용을 보존한 독립적으로 읽을 수 있는 유효한 MSG로 저장한다. 기존 파일 바이트가 없는 저장소형 첨부에 가상의 원본 파일 해시를 요구하지 않고 저장 결과의 형식·내용 보존으로 검증한다. 사용자가 나중에 열기 버튼으로 저장된 일반 이메일 MSG를 선택하는 것은 기존 단일 문서 열람 흐름에 해당한다.

## 4. 임시파일과 종료

메모리 처리를 우선 고려하되 구현에 필요한 임시파일은 허용한다. 정리 범위는 앱이 만든 임시파일, 캐시와 자체 열람기록이다. 사용자가 저장한 첨부와 Windows 자체 기록은 삭제 대상이 아니다. Windows 최근 항목 등 OS 기록까지 없애는 보장을 하지 않는다.

닫기 시에는 닫힌 문서의 자원을, 종료 버튼과 창 X에서는 해당 실행의 자원을 정리한다. 비정상 종료 또는 전원 차단 시 즉시 삭제까지 보장하지 않으며 다음 실행에서 남은 자원을 정리한다. 임시 경로의 소유권을 확인해 사용자 파일, 다른 앱의 파일, 실행 중인 다른 인스턴스의 파일을 삭제하지 않는다. 실제로 임시파일을 전혀 만들지 않는 설계라면 관련 테스트에서 생성되지 않았음을 확인하는 것으로 충족할 수 있다.

삭제 실패가 발생하면 성공한 것처럼 처리하지 않고 잔여물과 재시도 상태를 명확히 다룬다. 권한 실패나 사용 중인 파일 때문에 UI를 무기한 멈추게 하는 정리 방식은 피한다. 정상적인 접근 권한 조건에서 닫기·종료 직후 잔여물이 없어야 하며, 실패 주입 테스트는 정상 정리 성공을 대신하지 않는다.

## 5. GUI와 기술 선택

기본적인 창과 버튼·본문·첨부 목록 및 언어 변경 버튼으로 구성한다. 앱에서 추가하는 애니메이션, 그림자, 블러, 전환 효과, 장식용 이미지를 제외한다. Windows 창 관리자나 기본 컨트롤이 제공하는 통상적인 표현까지 OS 전역에서 바꾸라는 뜻은 아니다. 가독성과 본문 선택·복사를 유지한다.

### 화면 배치

다음 순서를 유지한다. 아래 그림은 한국어 UI의 구조를 설명하는 예시이며 실행 가능한 앱이나 실제 메일의 화면은 아니다.

```text
[열기] [닫기]                                  [언어 변경] [종료]

보내는 사람: 이름 <주소>           전송: YYYY-MM-DD HH:mm:ss
받는 사람: 이름 <주소>; 이름 <주소>
참조: 이름 <주소>
숨은참조: 정보 없음
제목: 제목은 기본 한 줄이며 길면
      두 줄, 세 줄 등으로 이어서 표시

본문
  메일 서식·표·삽입 이미지와 선택 가능한 텍스트

첨부파일
  파일이름1.pdf
  파일이름2.msg
```

첨부파일이 없는 경우 맨 아래 섹션은 다음과 같다.

```text
첨부파일
  없음
```

- 최상단 한 줄의 왼쪽 그룹은 열기 → 닫기, 오른쪽 그룹은 언어 변경 → 종료 순서다.
- 다음 줄에는 보내는 사람과 전송 일시를 함께 배치한다. 전송 일시가 긴 보내는 사람 값과 겹치지 않게 한다.
- 그 아래 받는 사람, 참조, 숨은참조는 각각 한 줄을 차지한다. 긴 값은 한 줄 구조를 유지하면서 가로 스크롤 등으로 전체를 확인·선택·복사할 수 있어야 한다.
- 이어서 제목을 배치한다. 한 줄을 기본으로 길면 자동 줄바꿈하며 두 줄·세 줄을 허용한다. 세 줄을 고정 상한으로 잘라내지 않는다.
- 제목 아래에는 본문, 그 아래 화면 구성의 맨 아래에는 첨부파일 섹션을 둔다. 본문과 첨부 목록이 길면 각각 스크롤로 전체 내용을 볼 수 있게 하며 파일명은 한 파일당 한 행을 유지한다.
- 네 UI 언어와 창 크기 변경에서도 순서·좌우 버튼 그룹과 가독성을 유지하고, 모든 첨부파일명은 전체 확인이 가능해야 한다.

구현 언어, GUI 프레임워크, MSG 파서와 HTML 렌더러는 아직 선택하지 않았다. native Win32/C++와 OS 렌더러는 검토 후보일 뿐 확정 기술이 아니다. 구현자는 Windows 기본 구성에서의 실제 가용성, x86 지원, 외부 설치 필요성, 배포 크기와 초기화 비용을 확인해 선택한다. 개발·빌드 도구 설치와 최종 사용자 PC의 추가 설치 금지는 구분한다.

### 다국어 UI

앱이 소유한 메뉴, 열기·닫기·종료·언어 변경 버튼, 메일 기본정보 항목 이름, 우클릭 복사, 상태 및 오류 문구는 한국어·영어·프랑스어·일본어로 제공한다. 번역 데이터는 모두 EXE에 넣는다. 별도 번역 파일이나 언어팩, 외부 번역 서비스를 요구하지 않는다. 네 언어를 추가한 최종 EXE에도 7~8MB 목표와 속도 우선 원칙을 적용한다.

한국어를 기본 언어 리소스로 둔다. 매 실행 현재 로그인 사용자의 Windows 표시 언어를 읽어 다음과 같이 결정한다. 날짜·숫자용 지역 형식이나 시스템 로캘을 기준으로 삼지 않는다. 예를 들어 Windows 표시 언어가 영어이고 지역 형식이 한국어인 경우 앱의 시작 언어는 영어다. 지역 변형도 같은 언어로 묶는다.

| Windows 표시 언어 | 시작할 앱 UI 언어 |
| --- | --- |
| ko, 예: ko-KR | 한국어 |
| en, 예: en-US·en-GB | 영어 |
| fr, 예: fr-FR·fr-CA | 프랑스어 |
| ja, 예: ja-JP | 일본어 |
| 그 외 언어, 예: de-DE·zh-CN | 영어 |
| 표시 언어 조회 실패 | 한국어 — 사용자가 채택한 예외 처리 기본값 |

언어 변경 버튼을 누르면 `한국어 / English / Français / 日本語` 중 선택할 수 있다. 앱을 재시작하지 않고 앱 소유 문구에 적용하며, 현재 MSG, 본문 선택과 첨부 목록을 유지한다. 앱 UI 언어를 변경해도 메일 제목·주소·본문·첨부파일명은 번역하거나 변경하지 않는다.

수동 선택은 현재 실행의 메모리에만 유지한다. 닫기 후 다른 MSG를 열 때는 유지하고, 앱을 종료했다가 다시 실행하면 Windows 표시 언어를 다시 읽는다. 언어 설정 파일이나 레지스트리 값을 남기지 않는다.

Windows 기본 열기·저장 대화상자에서 OS가 제공하는 버튼과 문구는 Windows의 표시 언어를 따른다. 앱이 넣는 제목·필터·오류 등 앱 소유 문구에는 선택한 언어를 적용한다. OS 문구를 강제로 번역하기 위해 무거운 별도 파일 선택 UI를 추가하지 않는다. 글자가 잘리거나 일본어 글리프가 누락되지 않고 프랑스어의 긴 문구를 읽을 수 있게 확인한다.

## 6. 검증 계획

아래 항목은 구현 후 사용할 검증 방법이다. 고객이 이미 제공한 시험 파일이나 실제 통과 기록이 있다는 의미는 아니다.

### 플랫폼과 샘플

- Windows 10 x86, Windows 10 x64, Windows 11 x64 각각에서 같은 최종 EXE의 해시를 기록한다.
- Outlook이나 별도 설치 의존성 없이 네트워크가 차단된 깨끗한 환경에서 첫 실행과 주요 흐름을 확인한다. OS 버전·빌드와 기본 설치 상태를 기록한다.
- 인터넷 연결이 가능한 시험 환경에서도 앱 및 호스팅 렌더러의 DNS·연결 요청 시도를 관찰한다. 원격 이미지·스타일·글꼴·스크립트·링크가 포함된 MSG로 시험하며, 요청이 방화벽에 막히거나 실패했다는 이유로 무통신으로 판정하지 않는다. 관찰한 프로세스 범위와 도구·조건을 기록한다.
- 최초 실행·본문 표시·언어 변경·닫기·종료와 외부 링크 클릭을 모두 포함해 외부 통신과 외부 브라우저 실행이 없는지 확인한다. Windows나 사용자의 독립적인 동기화 프로세스의 통신을 앱의 통신과 혼동하지 않는다.
- Windows 표시 언어 ko-KR·en-US·en-GB·fr-FR·fr-CA·ja-JP, 미지원 언어와 조회 실패를 시험한다. 표시 언어가 영어이고 지역 형식이 한국어인 경우를 포함한다. 네 언어 간 수동 전환, 문구 누락·잘림, 원문 보존, 닫기 후 유지 및 재실행 시 초기화를 확인한다.
- 상단 왼쪽 열기·닫기와 오른쪽 언어 변경·종료, 그 아래 보내는 사람과 전송 일시 한 줄 → 받는 사람 → 참조 → 숨은참조 → 제목 → 본문 → 첨부파일 순서를 확인한다.
- 여섯 메일 기본정보의 텍스트 선택·우클릭 복사와 전송 일시의 연·월·일·시·분·초 표시를 확인한다. 값이 없는 숨은참조·참조·전송 일시를 임의로 생성하거나 파일 시각으로 대체하지 않는지도 확인한다.
- 긴 주소값은 한 줄에서 전체 확인·복사가 가능한지, 긴 제목은 두 줄·세 줄 이상으로 표시되고 고정 세 줄에서 잘리지 않는지 확인한다. 네 언어와 창 크기 변경에서도 버튼·항목이 겹치지 않는지 확인한다.
- 일반 첨부가 0개·1개·여러 개인 경우 파일명당 한 행과 없음 표시를 확인한다. 본문 이미지만 있을 때도 일반 첨부 목록에는 없음이 표시되어야 한다.
- 본문 이미지·서명·로고가 본문에는 표시되고 첨부 목록에서는 제외되는지 확인한다. 일반 사진 파일 첨부는 목록에 표시되고 원본 바이트로 저장되는지 확인한다.
- 파일 형태 및 저장소형 MSG 첨부를 모두 저장해 독립적으로 읽을 수 있는 형식과 내용·내부 첨부 보존을 확인한다. 일정·연락처·암호화·권한 보호 등 지원 불가 유형은 이유를 안내하는지 확인한다.
- 일반 텍스트, HTML 서식·표·내부 이미지, 압축 RTF 본문을 포함하는 대표 MSG 및 첨부 없음·한 개·여러 개 사례로 본문 보존을 확인한다. 한글·영문 파일명, 중복 이름, 큰 첨부도 포함한다. 이는 테스트 범위이며 임의의 최대 지원 용량 선언이 아니다.
- 손상 파일, 파일 선택 취소, 저장 취소, 저장 실패, 닫기 후 재열기, 문서 교체, 종료 버튼, 창 X를 확인한다.
- 임시자원을 만든 상태의 강제 종료 후 재실행으로 잔여물 정리를 확인한다. 사용자 저장 파일과 다른 실행의 임시자원이 보존되는지도 확인한다.
- 해당 OS나 샘플을 확보하지 못하면 미검증으로 남긴다. x64에서 x86 실행 성공만으로 Windows 10 x86 실기 검증을 대신하지 않는다.

### 측정 구간과 기록

| 지표 | 시작 | 종료 |
| --- | --- | --- |
| 최초 실행 | OS에 프로세스 생성 요청 | 빈 뷰어의 열기 버튼이 입력 가능한 시점 |
| MSG 열기 | 파일 선택 확정 | 본문과 내부 이미지 표시 완료 및 선택·복사 가능한 시점 |
| 닫기 | 닫기 입력 | 본문 및 관련 임시자원이 정리된 빈 화면 |
| 종료 | 종료 버튼 또는 창 X 입력 | 관련 임시자원 정리와 프로세스 종료 모두 완료 |

사용자가 파일을 고르느라 소비한 시간은 열기 지표에서 제외한다. 본문만 먼저 표시하고 내부 이미지 처리 시간을 측정에서 빼지 않는다. 종료 요청만 보내고 프로세스가 남아 있는 상태를 종료 완료로 기록하지 않는다.

하드웨어, 저장장치, OS 빌드, 보안 검사 상태, 전원 모드, EXE 크기·해시, MSG 크기·특성과 측정 도구·반복 횟수를 기록한다. 첫 배포 후 실행, 재부팅 후 첫 실행, 반복 실행은 조건을 구분한다. 단순 재실행을 콜드 실행으로 표기하지 않는다. 조건별 원자료와 중앙값을 남기고 충분한 표본이 있으면 상위 지연 분포도 보고한다. 최대 작업 집합은 참고값으로 기록하며 별도 RAM 합격선을 만들지 않는다.

성능 개선안은 같은 환경·샘플·측정 구간으로 비교한다. 최소한 초기 동작 가능 빌드와 최종 빌드의 비교 또는 선택 가능한 대안의 비교 근거를 남겨 속도 우선 결정을 설명한다. 수치 SLA가 없으므로 실측값을 제시하되 '1초 보장' 같은 기준을 만들어 통과 판정하지 않는다. 보안 검사를 임의로 꺼서 얻은 속도를 기본 환경의 성능으로 보고하지 않는다.

사용자가 채택한 성능 판단 방식은 대표 MSG와 사용 환경에서 초기 구현을 측정한 뒤 판단 기준을 구체화하는 것이다. 아직 실제 사용자 파일·PC 사양·허용 대기시간 수치는 제공되지 않았으며, 이를 받은 것처럼 기록하지 않는다. 초기 검증에서는 출처와 크기·첨부·본문 특성이 명시된 대표 샘플과 시험 환경을 사용하고, 실제 사용 환경 자료를 확보하면 같은 측정 구간으로 비교한다. 구체적인 시간 합격선 없이 절대 성능을 보장하지 않는다.

### 구현 완료 때의 산출물

- `dist/MsgViewer.exe`: 실제 공용 배포 EXE. 개발용 소스·보고서를 배포 EXE에 덧붙여 설치 요구로 만들지 않는다.
- `reports/acceptance.md`: AC별 통과·실패·미검증, OS별 결과, 시각 비교·복사·첨부 무결성·정리 근거와 크기 목표 상태.
- `reports/performance.csv`: 원 측정값 및 빌드·환경·샘플 식별자. 상세 조건과 집계는 acceptance 보고서에서 연결한다.

필수 동작과 환경 중 미검증 항목이 있으면 전체 검증 완료로 보고하지 않는다. 보고서 파일의 존재, 명세 자체의 QA 통과, 스키마 검증 통과는 앱의 동작 검증과 별개다. 크기 목표 초과나 알려진 본문 호환성 제한도 결과에 드러내야 한다.

## 7. 결정 출처

이 명세는 같은 대화에서 사용자가 최종 목표와 동작을 확인하고 '맞음 — 이 내용으로 명세 작성'으로 승인한 결과다. 5MB 이하나 크기·속도·메모리의 동등 우선순위는 최종 요구가 아니다. 최신 결정은 7~8MB 목표, 속도 우선, RAM 추가 사용 허용이다.

수정 2에서는 인터넷 사용 금지, 네 언어 UI, 매 실행 Windows 언어에 따른 자동 선택과 수동 변경의 실행 중 유지·종료 후 미저장을 확정했다. 수정 3에서는 사용자의 '모두 제안하는 안 그대로 해줘'라는 답변으로 Windows 표시 언어 기준, 다섯 메일 기본정보의 표시·복사, 일반 이메일 우선 지원과 지원 불가 이유 안내, 첨부 MSG 저장, 본문 이미지의 첨부 목록 제외 및 초기 구현 후 대표 환경에서의 성능 판단을 채택했다.

표시 언어 조회 실패 시 한국어, Windows 기본 열기·저장 창의 OS 표시 언어 유지, 텍스트 복사 보장과 서식 복사 선택 사항도 이번에 사용자 승인 기본값이 되었다. 구현 언어와 렌더러는 조건을 충족하는 기술을 구현자가 선택한다. 이전 명세와 검토 기록은 `docs/history/revision-1/` 및 `docs/history/revision-2/`에 보존했다.

수정 4에서는 x64의 이점을 검토한 뒤 사용자가 x86 유지와 구체적인 화면 순서를 지시했다. x64 전용으로 바꾼 적은 없으며 기존 공용 x86 EXE 조건을 유지한다. 숨은참조, 전송 연·월·일·시·분·초, 제목의 여러 줄 표시, 하단 첨부 목록의 파일당 한 줄 및 없음 표시는 이번 명시 요청으로 확정됐다. 직전 명세와 검토 기록은 `docs/history/revision-3/`에 보존했다.

현재 환경에 호출 가능한 Ouroboros MCP 인터뷰 도구가 없어 대화 기반 로컬 Seed 경로를 사용했다. MCP 인터뷰 ID를 만들지 않았다. Seed의 `ambiguity_score` 0.15는 설치된 스키마 기본값이며 도구로 측정한 수치가 아니다. 별도 QA 점수는 이 명세에 대한 로컬 검토 결과로만 취급한다.
