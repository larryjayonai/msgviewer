# 수정 3 — 세부 동작과 기본값 확정

사용자의 '모두 제안하는 안 그대로 해줘'라는 답변으로 아래 제안과 기본값을 채택했다. 기존 Seed를 직접 수정했으며 새 인터뷰·MCP 세션을 만들거나 앱 구현을 시작하지 않았다.

## 채택한 제안

1. 매 실행 Windows 표시 언어를 읽는다. 날짜·숫자의 지역 형식이나 시스템 로캘은 기준이 아니다. ko/en/fr/ja는 해당 언어, 그 외에는 영어다. 수동 선택은 현재 실행에서만 유지한다.
2. 제목·보낸 사람·받는 사람·참조·발신 날짜를 본문 위에 표시하고 각 값의 선택·우클릭 텍스트 복사를 지원한다. 항목 이름은 UI 언어를 따르며 실제 메일 값은 번역하지 않는다.
3. 일반 이메일 MSG를 우선 지원한다. 지원하지 못하는 일정·연락처·암호화·권한 보호 메시지에는 이유를 안내한다. 첨부된 MSG는 저장만 지원한다. 저장소형 첨부도 내용과 내부 첨부를 보존한 유효한 MSG로 저장한다.
4. 본문 삽입·서명·로고 이미지는 본문에 표시하고 첨부 목록에서 제외한다. 일반 이미지 파일 첨부는 목록과 저장 대상으로 유지한다.
5. 초기 동작 가능 빌드를 대표 MSG와 명시된 사용 환경에서 측정한 뒤 성능 판단을 구체화한다. 실제 사용자 파일·PC 사양이 이미 제공됐다고 가정하거나 임의의 시간 SLA·RAM 상한을 추가하지 않는다.

사용자는 함께 제시한 세 기본값도 채택했다. 표시 언어 조회 실패 시 한국어를 사용하고, Windows 기본 파일 대화상자의 OS 소유 문구는 Windows 표시 언어를 따르며, 복사는 텍스트를 보장하되 서식 복사는 필수가 아니다.

## 수정 범위

- AC-03~05와 AC-08·10을 구체화하고 AC-11에 메일 기본정보의 표시·복사를 추가했다.
- 기존 ontology 이름과 필드를 보존하고 승인된 `message_headers` 필드를 추가했다.
- `localization_policy`의 언어 기준을 Windows 표시 언어로 확정하고 예외 처리 기본값도 사용자 승인으로 기록했다.
- 완료 조건과 검증 계획에 메일 기본정보, 본문 이미지 분류, 첨부 MSG 저장, 지원 불가 유형의 안내 및 표시 언어와 지역 형식이 다른 사례를 반영했다.
- 단일 x86 EXE, 추가 설치 금지, 인터넷 요청 금지, 네 언어 UI, 7~8MB 목표, 속도 우선, 첨부 저장 및 임시자원 정리 요구를 유지했다.
- 수정 2의 명세·검토 기록은 `history/revision-2/`에 보존했으며 파일 해시를 확인했다.

## 검토 결과

로컬 문서 QA 1/5회차 **0.98, pass**. 필수 수정 제안은 없다. 설치된 Ouroboros 0.51.7 Seed 스키마와 중복 YAML 키, 11개 AC 식별자, 6개 ontology 필드, 기존 ID·필드 보존, 언어 기준, 이전 스냅샷 해시 및 텍스트 무결성 검사를 통과했다.

최신 결과와 파일 해시는 `seed-qa.json`, `seed-mechanical.json`, `seed-audit.json`에 기록했다. 실제 EXE의 동작·크기·속도는 아직 검증하지 않았다.
